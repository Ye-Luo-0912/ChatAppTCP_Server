# ChatApp performance gate

Cross-platform gate for a `benchmark-report.json` generated by the performance orchestrator.

```bash
dotnet run --project tools/ChatApp.Performance.Gate -- \
  --report path/to/benchmark-report.json \
  --max-p95-ms 300 \
  --max-jetstream-pending 0 \
  --max-outbox-pending 16 \
  --max-outbox-oldest-age-seconds 5 \
  --output gate-result.json
```

It returns zero only when the benchmark passed, pipeline error rate/p95 meet the thresholds, and the final JetStream/Outbox backlog is within the configured limits. Use it in scheduled performance CI, not normal pull-request builds.

Optional conversation-stage checks (from the pipeline source report `Latencies`):

```bash
dotnet run --project tools/ChatApp.Performance.Gate -- \
  --report path/to/benchmark-report.json \
  --require-conversation-stages \
  --max-history-p95-ms 50 \
  --max-conversation-list-p95-ms 50 \
  --max-sync-bootstrap-p95-ms 100 \
  --output gate-result.json
```

`--require-conversation-stages` fails closed if `history_query` / `conversation_list_query` / `sync_bootstrap` are missing. Stage p95 thresholds are optional and only evaluated when provided.

The gate fails closed: a missing required metric also fails the run. JetStream and Outbox pending values are summed across replicas, while the oldest Outbox age uses the worst replica value.

On the Linux test host, make the generated `gate-result.json` a CI artifact:

```bash
export DOTNET_ROOT="$HOME/.dotnet"
export PATH="$DOTNET_ROOT:$PATH"

dotnet run --project tools/ChatApp.Performance.Gate/ChatApp.Performance.Gate.csproj \
  -c Release --no-build -- \
  --report "$REPORT_DIRECTORY/benchmark-report.json" \
  --output "$REPORT_DIRECTORY/gate-result.json"
```

Run the 8–24 hour soak and this gate in a scheduled, self-hosted Linux job. The repository currently has no configured Git remote or runner, so registering that runner remains an environment setup task rather than an unverified source-code change.
